# Ledgerly Capacitor Android Application Design

**Date:** 2026-07-30

**Status:** Approved

## Objective

Create a production-ready Android application for Ledgerly with Capacitor 8
from a fresh, reproducible copy of the existing frontend. The native wrapper
must preserve the web application's API contracts, authentication behavior,
business logic, routing, state management, and visual language while adding
the Android-specific lifecycle, system UI, safe-area, keyboard, offline,
branding, security, build, and release capabilities required for a polished
store-ready application.

## Repository and history design

The root repository begins with a baseline commit containing the exact tracked
frontend snapshot and a comprehensive `.gitignore`. The baseline commit is
created on `main`; all Android work is performed on
`feature/capacitor-android-app`.

The root `.gitignore` excludes:

- the preserved `ledgerly-web/` and `ledgerly-api/` reference repositories;
- Node dependency, coverage, cache, log, and build output;
- Capacitor transient output;
- Android `.gradle`, build, capture, local SDK, and generated IDE state;
- IntelliJ/Android Studio, VS Code, and operating-system metadata;
- `.env` files except explicit example files;
- keystores, `key.properties`, signing properties, certificates,
  `google-services.json`, and service-account material;
- APK, AAB, mapping, native symbols, and other release artifacts.

Generated Android source, resources, Gradle wrapper files, and deterministic
configuration are committed. Local SDK paths, caches, signing credentials,
and built artifacts are never committed.

## Application architecture

The imported React application remains the product implementation. Capacitor
is a platform adapter at the outer edge of the application rather than a new
state-management or navigation layer.

### Web/native boundary

Native behavior is centralized under `src/platform`:

- `runtime.ts` detects native Android without changing browser behavior.
- `system-ui.ts` maps Ledgerly's resolved light/dark theme to Capacitor's
  built-in status-bar and navigation-bar appearance.
- `network.ts` exposes guarded subscription plus `refreshNetworkState()` and
  updates TanStack Query's `onlineManager`.
- `keyboard.ts` exposes guarded subscription plus
  `resetNativeKeyboardState()`; browser visual-viewport fallback stays outside
  plugin ownership.
- `preferences.ts` accepts abortable hydration, mirrors only the five existing
  non-sensitive keys, and serializes native mutations FIFO per key.
- `back-layer-stack.ts` registers dismissible overlays in visual stacking
  order so native back closes exactly one top layer.
- `back-navigation.ts` applies the ordered Android back policy.
- `external-links.ts` validates and opens external URLs.
- `haptics.ts` provides no-op-safe, intentional native feedback.
- `startup.ts` releases the native splash only when the first stable frontend
  frame is ready and owns an AbortController for bounded preference hydration.
- `native-app-state.ts` exposes immutable snapshots with exact field
  `nativeKeyboard: KeyboardState | null`; null preserves browser fallback.
  `getNativeAppStateServerSnapshot()` returns one stable frozen singleton as
  `useSyncExternalStore`'s server snapshot.
- `native-app-bridge.tsx` is the sole App, Network, and Keyboard subscription
  owner and connects that store to React Router, TanStack Query, and theme.

`NativeAppBridge` is mounted once inside the existing router, QueryClient, and
app provider and receives resolved theme, demo mode, and authentication state.
Pages, the shell, and hooks do not subscribe to Capacitor plugins directly. No
App URL listener exists because deep links are excluded.

### Android back policy

The hardware/system back action is handled in this order:

1. Dismiss the most recently visible registered owner: shared `BottomSheet`,
   desktop `DesktopDialog`, desktop `WorkspaceSearch`, or
   `DesktopWorkspaceSwitcher`.
2. Remove URL modal keys `add`/`claim` with replace navigation while preserving
   pathname, unrelated ordered/repeated query values, hash, and location state.
3. Navigate to prior router/browser history when Capacitor `canGoBack` or the
   history index proves a usable entry.
4. Without usable history, replace-navigate non-root authenticated routes to
   `/app/home` and non-root unauthenticated routes to `/`.
5. Exit only at `/`, directly entered `/login`, or authenticated `/app/home`.

An unauthenticated `/app/home` is not an exit root. Overlay registration lives
only at those four shared owners, not their callers, so one back press closes
one layer through its existing close-and-refocus path. Android predictive
back is enabled in the manifest; no deep-link route is introduced.

### Lifecycle

The App plugin provides app-state and back-button events. `NativeAppBridge`
owns the only App/Network/Keyboard listeners. On resume it reapplies the current
system bars, calls `refreshNetworkState()` and
`resetNativeKeyboardState()`, updates `focusManager`, and invalidates eligible
active queries only after an offline-to-online transition when authenticated
and not in demo mode. QueryClient uses `refetchOnReconnect: false`, leaving one
reconnect refetch owner. Listener cleanup is idempotent and late events are
ignored.

No token is logged or moved to native preferences. Ledgerly's live bearer
token remains memory-only, so a terminated live session returns to login. Before
native React render, the five allowed preference keys are hydrated with an
AbortSignal. The timeout owns and aborts its controller so a late native read
cannot mutate storage after startup proceeds; failure remains non-fatal and
cannot leave the splash stuck.

### Network behavior

The existing non-blocking offline banner consumes the single immutable native
state store. Capacitor Network is authoritative on native Android; browser
online/offline events remain the adapter fallback. Guarded subscriptions ignore
late callbacks, `refreshNetworkState()` owns explicit resume reads, and the
bridge alone invalidates eligible authenticated non-demo queries once on
reconnect. It never replaces real HTTP/API errors or mounted form state.

### External links

All programmatic external navigation accepts only normalized public HTTPS. The
raw and normalized values are each capped at 4,096 characters. WhatsApp uses
the exact `wa.me` host; its subdomains and lookalikes are rejected. Credentials,
control/whitespace characters, non-HTTPS schemes, protocol-relative input,
trailing-dot or single-label hosts, localhost/private/reserved/example names,
`home.arpa`, non-public IP forms, and local-use/private-address NAT64 embeddings
are rejected.

The product has no mail or phone launcher, so `mailto:` and `tel:` remain
invalid. Native Browser receives only the frozen normalized URL; web behavior
uses `_blank` with `noopener,noreferrer`. WhatsApp delivery is asynchronous and
keeps the existing 4,096-character privacy-reviewed payload ceiling.

### Preferences and authentication

Capacitor Preferences is limited to `mt-demo`, `mt-user-name`, `mt-workspace`,
`mt-privacy`, and `mt-theme`. App-context direct local-storage writes are
replaced by the adapter, not duplicated: the adapter performs the synchronous
local mirror and queues native set/remove operations FIFO per key. Abortable
hydration checks its signal between awaited operations. Credentials remain
memory-only; no token, broad Preferences operation, or secure-storage feature
is introduced without a refresh-token contract.

### Haptics

Haptics are limited to meaningful native interactions such as mobile
navigation selection and successful quick actions. Browser and unsupported
device paths are no-ops. Financial operations never depend on haptic success.

## System UI and safe areas

### Status bar

`system-ui.ts` is the only JavaScript system-bar controller. It uses
Capacitor 8.4.2's built-in `SystemBars` core plugin to select light or dark
status icons from the resolved Ledgerly theme. Android edge-to-edge remains
enabled, the bar itself stays transparent, and the current web-root canvas is
the visible background, so an app-selected theme can differ from Android
system night mode. Native theme resources match the startup canvas before the
WebView paints. The controller runs on theme change and resume.

### Navigation bar

Capacitor 8.4.2's built-in `SystemBars` core plugin controls navigation icon
contrast independently from status-bar contrast. Gesture navigation remains
transparent over the current web-root canvas; three-button mode may add only
Android's platform contrast scrim and must not reveal a white strip in dark
app theme. This is tested after selecting an app theme independently of system
night mode. The generated `MainActivity` remains unchanged. Release WebView debugging is
disabled through Capacitor configuration and verified from the merged release
manifest/build rather than by adding a redundant native override.

### Safe areas

The root CSS defines the required public variables:

- `--safe-area-top`
- `--safe-area-right`
- `--safe-area-bottom`
- `--safe-area-left`

Each prefers Capacitor's injected `--safe-area-inset-*` variable and falls
back to `env(safe-area-inset-*, 0px)`. Existing `--safe-top`, `--safe-right`,
`--safe-bottom`, and `--safe-left` variables become aliases so current layouts
continue to work without page-by-page padding. The HTML viewport uses
`viewport-fit=cover`, which activates Capacitor's CSS inset handling.
Application chrome, mobile navigation, sheets, and offline banners consume
the centralized variables once at their shared boundary. There is no global
`html`/`body`/`#root`, nested, or per-page padding that double-counts an inset.

### Keyboard

The Keyboard configuration keeps `resize: "native"` for supported platforms
and enables Android's `resizeOnFullScreen` workaround, but Android behavior is
not assumed from the iOS-only `resize` option. The activity intentionally has
no `android:windowSoftInputMode` override: Capacitor 8.4 SystemBars/IME
handling owns the insets, while the fullscreen workaround covers WebView
resizing. An `adjustResize` override is added only if emulator evidence first
produces a failing regression case. Central keyboard listeners expose
visibility and measured height through a document
data attribute and `--keyboard-height`. The external store publishes
`nativeKeyboard: KeyboardState | null`; non-null is authoritative, while null
means native state is unavailable and activates `useSoftKeyboard`'s existing
browser `visualViewport` fallback. Fixed mobile navigation hides while typing; dialogs,
sheets, and form containers preserve scrollability. `--keyboard-height` is a
measurement signal, not global IME padding added on top of WebView resize or a
second safe-area bottom.

## Native Android design

### SDK and Gradle

The generated Capacitor Android project uses namespace/application ID
`io.github.d4rkninja.ledgerly`, minimum SDK 24, compile SDK 36, and target SDK
36. The project commits `gradlew`, `gradlew.bat`, and
`gradle/wrapper/gradle-wrapper.properties`. Build commands always invoke the
wrapper.

### Manifest and permissions

The owned main source manifest:

- declares only `android.permission.INTERNET`;
- declares the exported launcher activity explicitly;
- enables hardware acceleration;
- disables cleartext traffic;
- applies the restrictive production network-security configuration;
- disables application backup and defines data-extraction/backup rules;
- enables Android's predictive-back callback;
- does not lock orientation;
- contains no camera, microphone, storage, contacts, location, or notification
  permission;
- adds no deep-link intent filter because the current frontend has no owned,
  verified application-link domain;
- retains Capacitor's file provider only where required by the generated
  runtime.

Merged debug and release manifests contain exactly INTERNET,
ACCESS_NETWORK_STATE, and VIBRATE; the latter two normal permissions come from
the official Network and Haptics plugins and are not dangerous runtime prompts.
Release WebView debugging is forcibly disabled. Debug builds remain debuggable
through Android's standard debuggable build type.

### Themes

Native resources define centralized light and dark colors for:

- splash background;
- application window background;
- status-bar protection/background;
- navigation-bar and divider;
- system icon appearance.

Separate day/night base and launch themes prevent a white or black startup
flash. Android 12+ uses the platform SplashScreen API with a padded adaptive
logo and `postSplashScreenTheme`; older supported versions use the equivalent
compat launch theme. The web root background matches the native theme palette.

### Splash lifecycle

The native splash is not time-delayed arbitrarily. It remains visible until:

1. React has mounted;
2. the first animation frame has completed;
3. document fonts have either loaded or reached a short bounded timeout.

The web bridge then hides it with a short fade. A hard upper bound prevents a
broken frontend from leaving the user on a permanent splash screen.

### Branding assets

The canonical source is `public/logo.svg`, whose brand colors are `#17483A`,
`#A6B58A`, and `#20272B`. Deterministic high-resolution sources add the
required adaptive safe-zone padding without redrawing the mark.

Generated and committed assets include:

- legacy launcher icons for every Android density;
- round launcher icons;
- adaptive foreground and background resources;
- Android 13+ monochrome themed icon;
- padded light and dark splash sources and density resources;
- a 512-by-512 Play Store source icon.

The default Capacitor icon and splash assets are fully replaced. No
notification icon is generated because notifications are not used.

## Build and automation design

### Command surface

`package.json` exposes:

- `android:doctor`
- `android:setup`
- `android:sync`
- `android:assets`
- `android:open`
- `android:run`
- `android:build`
- `android:build:debug`
- `android:build:release`
- `android:test`
- `android:clean`

The package scripts call a cross-platform Node orchestrator. The required
`scripts/create-android-app.sh` and a Windows
`scripts/create-android-app.ps1` companion invoke the same orchestrator so
behavior cannot drift by shell. `android:sync` always rebuilds React before
Capacitor sync. Both debug and release build commands rebuild React, apply the
owned native overlay, sync the resulting `dist`, run the matching Gradle task,
and verify the expected artifact. Release validation happens before any build
or sync side effect, so a stale debug bundle can never become a release AAB.

### Idempotent setup

The setup command:

1. parses options and, for `--release`, validates the production API URL before
   any build or sync side effect;
2. validates Node 22.22+ within major 22, or Node 24+, rejecting Node 23,
   earlier Node 22 releases, and unsupported majors; it then validates npm,
   Java/Javac, Android SDK variables, SDK 36, build tools, and adb without a
   not-yet-generated wrapper;
3. installs dependencies with `npm ci`, runs `npm run test:scripts`, and then
   runs Capacitor doctor;
4. executes the complete frontend check, whose final step is the production
   build, and verifies a fresh `dist/index.html`;
5. initializes Capacitor configuration only when absent;
6. adds Android only when `android/` is absent, but rejects a partial existing
   project rather than overwriting it;
7. validates generated wrapper/template versions, locked Capacitor 8.4.2
   identity, app ID/namespace, SDK values, and plugin metadata;
8. regenerates branded resources; the lazy loader translates only a missing
   top-level `android-assets.mjs`, never one of its dependency failures;
9. applies a deterministic native overlay containing manifest, theme,
   security, backup, and icon files;
10. runs `cap sync android`;
11. runs Gradle dependency, unit-test, lint, and `assembleDebug` checks and
    verifies the APK so the one command always produces an installable artifact
    from the current React build;
12. for `--release`, runs `bundleRelease` and verifies the release AAB;
13. opens Android Studio only when `--open` is supplied;
14. fails on the first unsuccessful command with the failed step and recovery
    guidance.

Repeated execution produces identical tracked files under a committed
.gitattributes policy: LF shell/`gradlew`, CRLF batch files, and binary
artifacts. It never duplicates manifest entries, Gradle blocks, resources, or
plugins. The explicit ownership manifest removes stale owned paths, preserves
unrelated generated files, rejects symlink escape, and validates byte parity.

### API environment

Debug without `VITE_API_BASE_URL` is demo-only. Live emulator debug permits
exactly `http://10.0.2.2:8080/api/v1` with its debug-only network/mixed-content
policy. Every release entry point validates before any build or sync side
effect and requires canonical credential-free HTTPS with exact `/api/v1`. It
rejects reserved/example/local/private names, trailing-dot/single-label hosts,
all IP literals, credentials, query/fragment, and non-canonical paths.

A release AAB requires the operator's actual owned production API. If none is
available, all release AAB work remains blocked and the report records that
external prerequisite; no example or invented hostname is substituted. The
packaged origin is `https://localhost`, so the API must return exact
`Access-Control-Allow-Origin: https://localhost`, credentials true, allowed
methods, and `Authorization, Content-Type`; cookie sessions additionally need
`SameSite=None; Secure`.

### Signing

The four external values are upload-store file, store password, key alias, and
key password. All absent produces, only when a real API exists, an `unsigned
verification AAB`. All four non-empty values with a regular external keystore
may produce a `signed upload candidate`; any partial/empty set fails closed.
The orchestrator strips them from npm, Vite, Capacitor, doctor, debug Gradle,
and logs and exposes the complete set only to `bundleRelease`, never on a
printed command line.

A candidate is called signed only after `jarsigner` inspection matches the
expected certificate fingerprint. Neither unsigned verification nor signed
candidate is claimed Play-deployable; owner-controlled Play upload/validation
remains external. Keystores, passwords, and signing files remain untracked.

## Testing and verification

### Automated frontend and platform tests

Vitest, jsdom, and React Testing Library cover:

- native/browser runtime detection;
- URL validation and native/browser opening;
- back-order behavior for overlays, modal query parameters, route history,
  and exit;
- light/dark system-bar mapping and resume reapplication;
- splash release readiness and timeout;
- native/browser network subscriptions and one-time reconnect invalidation;
- immutable `nativeKeyboard` null/fallback semantics plus stable frozen
  `getServerSnapshot` identity in SSR/jsdom;
- native and visual-viewport keyboard state;
- setup-script/doctor rejection for Node 22.13-22.21 and Node 23, acceptance
  of Node 22.22+ within major 22, or Node 24+, plus command ordering,
  idempotence, and release API URL enforcement.

The existing `typecheck`, `lint`, production build, and Node script suite remain
mandatory. `npm audit` and `npm audit --omit=dev` must both report zero
vulnerabilities, including zero Router advisories with exact
`react-router@8.3.0`. Tests do not mock away claimed behavior.

### Android build checks

The Gradle wrapper runs:

- dependency resolution;
- `testDebugUnitTest`;
- `lintDebug`;
- `assembleDebug`;
- `bundleRelease`;

A stale artifact is deleted before its producing task. Each fresh APK/AAB is
inspected for identity, versions, SDKs, debuggable/permission/signing state,
ZIP integrity, and WebView assets, then receives ignored `.sha256` and
`.metadata.json` sidecars tying its hash to Git, `dist`, overlay, API origin,
signing label, and inspection results. A release AAB is absent by design when
the real production API prerequisite is absent.

### Emulator matrix

The exact `Pixel_9` API 36 AVD is driven with the installed
`android-emulator-qa` `ui_tree_summarize.py` and `ui_pick.py` scripts. Every
tap uses UI-tree-derived centers; a missing WebView node is fixed as an
accessibility defect rather than guessed from a screenshot. It is used for:

- cold and warm launch;
- native-to-web splash transition;
- light, dark, and system theme;
- status/navigation icon contrast;
- login, signup, OTP-style inputs where present, forms, search, dialogs, and
  text areas with the keyboard;
- top-overlay/modal/history behavior, exact root-only exit, and non-root
  replacement fallback;
- network loss/recovery and exact local-debug API policy when a backend exists;
- normalized public HTTPS/exact `wa.me` links and unsafe-link rejection;
- background and resume;
- portrait and landscape;
- representative small-phone, large-phone, and tablet dimensions;
- frontend API requests and the documented terminated-session behavior.

Where a live API account or release signing secret is unavailable, the final
report distinguishes that manual prerequisite from verified demo/local
behavior. No unperformed physical-device or production-account test is
reported as passing.

## Explicit exclusions

- No frontend API, business-domain, authentication, or state-management
  redesign.
- No fake offline data layer or service worker.
- No local-notification plugin or permission without a real scheduling
  feature.
- No camera, location, contacts, microphone, broad storage, or notification
  permission.
- No production live-reload server, cleartext endpoint, wildcard navigation
  allow-list, embedded secret, or committed signing credential.
- No deep-link declaration without an owned HTTPS domain and matching backend
  association file.
- No claim of persistent live authentication after process termination; the
  existing memory-only token model is preserved.
